# Flutter Widget

Build UI like it belongs in the repo.

- Look at nearby widgets before adding a new pattern.
- Use the existing theme, spacing, typography, localization, and responsive helpers.
- Keep widgets small and composable.
- Do not put business logic, networking, persistence, or heavy transforms in widgets.
- Prefer composition over flag-heavy widget APIs.
- Keep rebuild scope small when state changes often.
- Preserve accessibility, text scaling, loading, empty, and error states.

When reporting back, mention the existing UI pattern you followed and how you validated the behavior.

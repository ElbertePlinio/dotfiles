# Design modes

Choose one primary mode. A task can include a smaller secondary mode, but avoid vague hybrids.

## Greenfield

Establish product intent, information architecture, visual premise, interaction model, and a small reusable foundation. Start with one representative surface before expanding a full system.

## Unfamiliar-repo audit

Learn before changing. Inspect the running product, repeated patterns, tokens, components, platform norms, and obvious inconsistencies. Separate intentional character from accidental drift. Recommend improvements by user impact, then reclassify the accepted improvements as `targeted` or `preserve` and continue under the same design lead.

## Preserve

Add a feature that should feel native to an already coherent product. Reuse its grammar and make the smallest new design decision set.

## Targeted improvement

Fix a named weakness such as hierarchy, density, navigation, responsiveness, feedback, accessibility, or motion. Keep unrelated surfaces stable and define before/after proof.

## Overhaul

Use only when the current system cannot support the product goal. State what remains recognizable, what changes, migration boundaries, and how regressions will be caught. Do not use "redesign" as permission to replace everything.

## Surface notes

- **Product UI:** optimize comprehension, state clarity, task completion, and repeated daily use before spectacle.
- **Desktop/native:** respect window resizing, keyboard paths, system conventions, density, and persistent state.
- **Mobile:** prioritize reachability, interruption recovery, input behavior, and small-screen hierarchy.
- **Marketing:** create one memorable premise while keeping the product and conversion path legible.
- **Reference reproduction:** translate principles into the current product; do not trace another brand's identity.
